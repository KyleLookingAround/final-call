# Brief: A check on PR titles and descriptions

The coordinator's brief for a small runbook change. The commit hook keeps commit messages free of attribution, but nothing checks a PR's title or description. Three PRs on 27 Sep 2026 opened with a "Generated by" footer and a session link, which the tools add when a PR is opened (#38, #39, #41). Two reached review before someone removed them by hand. No game code.

## Goal and what it may touch

- A workflow, `.github/workflows/description.yml`, on `pull_request` (`opened`, `edited`, `reopened`, `synchronize`), with one fast job: `actions/github-script`, no checkout. It fails if the PR's title or description mentions Claude or Anthropic, has a "Generated with/by" line, a `claude.ai` or `claude.com` link, a `Co-authored-by` or `Claude-Session` line. The failure message quotes each offending line and says how to fix it: edit the description; no push is needed, since editing re-runs the check.
- It is a separate workflow so that editing a description re-runs only this check, not `npm run check`. Use the same patterns as `.githooks/commit-msg`, with a comment in each naming the other so they stay alike. File paths count too: a description calls `CLAUDE.md` "the project notes" and `.claude/` "editor settings", as commit messages already do.
- Prove it on its own PR, and link the three runs there: opened clean (pass); a footer added by editing the description (fail, naming the line); the footer removed (pass).
- Branch `feature/description-check` from `main`, one PR.
- It may touch: `.github/workflows/description.yml` (new), `.githooks/commit-msg` (the cross-reference comment only), the `steward` playbook's "Before every push" (one line: the Description check, and that the tools may add a footer when a PR opens, so read the description back), the project notes' "Commits, PRs and attribution" (one line naming the check), a line under "The runbook" in `docs/ROADMAP.md`, `docs/LESSONS.md`, and this brief as `docs/briefs/description-check.md`. Nothing in `src/game/`, and no change to `checks.yml`, `balance.yml`, `parts.yml` or `pages.yml`.

- Only for something irreversible or outside this brief.
