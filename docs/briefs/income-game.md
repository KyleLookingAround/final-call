# Brief: Income from Final Call, with nothing intrusive and no pay-to-win

The owner asked on 28 Sep 2026 for a session on how Final Call can earn money: no ads, nothing intrusive, and nothing that lets a player pay to win. The owner floated a paid 16× speed as an example. This session researches and writes a spec for the owner to approve. It builds nothing.

## Goal and what it may touch

- Write `docs/specs/income.md` from `docs/specs/TEMPLATE.md`, marked `Proposed`. It must:
  - List the realistic options for a free browser game on GitHub Pages with saves kept on the device (no server, no accounts), and rank them by likely income against the owner's effort. Start from what already exists: the Ko-fi link (`docs/specs/kofi-link.md`). Consider at least: a one-off "supporter" unlock (cosmetics such as liveries, terminal themes, photo-mode frames, or convenience such as 16× speed and extra save slots); a pay-what-you-want download on itch.io; a desktop or phone build (Steam, app stores) and what each costs to list; Ko-fi or GitHub Sponsors tiers; and anything else that fits.
  - Test each against the owner's rules: no ads, nothing between the player and the game, no pay-to-win. Say plainly whether 16× speed counts as pay-to-win here (it changes pacing and bot-measured balance, not what a player can build) and suggest the safest form.
  - Say how an unlock could work with no server: a licence code from the seller (itch.io, Ko-fi shop or Gumroad) checked on the device, what that costs in cheating, and why that's acceptable or not. Saves stay on the device.
  - Give honest numbers: typical takings for a small free web game, with sources, so the owner can judge whether it's worth it.
  - End with **Choices** for the owner, each with the default you'd take, and an **Order of work** of parts (each one PR from its own brief) for the default choice.
- Branch `feature/income-spec` from `main`, one draft PR. It may touch: `docs/specs/income.md` (new), `docs/roadmap.d/` (one new item file), this brief as `docs/briefs/income-game.md`, and its own `docs/lessons/` file. No game code.
