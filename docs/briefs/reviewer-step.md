# Brief: A fresh review before each PR opens (runbook experiment [E])

The coordinator's brief for a runbook experiment the owner chose on 27 Sep 2026. Before a session opens a PR, a helper that hasn't seen the work reviews it. Sessions already have the tool for starting helper agents (`Agent`), and the `code-review` skill. No game code.

## Goal and what it may touch

- A step in the `feature` playbook, between "Prove it" and "Ship". Before opening the PR, start one fresh reviewer, a helper agent or the `code-review` skill at medium effort. Give it the diff against `main`, the brief and the project notes, and ask for:
  - bugs;
  - broken rules: the owner's preferences, saved fields, `rnd()`, `R.sim`, UK English;
  - lines outside the diff the change makes wrong: the README, code comments, the project notes, `docs/SYSTEMS.md`. #39 missed the README;
  - anything in the PR's title or description that the project notes don't allow.
- The session fixes what it agrees with, and says in the PR what the review found and what it fixed or left. Helpers are for reviewing and reading, never for building: building stays in separate sessions with their own PRs.
- Record it as experiment [E]:
  - a line under "The runbook" in `docs/ROADMAP.md`;
  - a decision record in `docs/decisions/`, since it sets a rule;
  - how it's measured: findings per PR that CI or a later review would otherwise have caught, and the review's cost. Measure on the next five PRs, then keep or remove it.
- Add one line to the "Checks" list in `.github/pull_request_template.md`, reading "A fresh review before opening: what it found and what changed". PR descriptions may not name the tool or say "AI" or "assistant" (the project notes), so the line doesn't either.
- Try it on its own PR first, and report what the review found.
- Branch `feature/reviewer-step` from `main`, one PR.
- It may touch: `.claude/skills/feature/SKILL.md` (the new step), `.claude/skills/steward/SKILL.md` (one line under "Before every push" if needed), `.github/pull_request_template.md` (that one line), a new record in `docs/decisions/`, `docs/ROADMAP.md`, `docs/LESSONS.md`, and this brief as `docs/briefs/reviewer-step.md`. Nothing in `src/game/` or `tools/`.

## When to stop and ask

- Only for something irreversible or outside this brief.
- Otherwise, if it truly needs the owner: open an issue labelled `needs-owner` with the question and the option it will take by default, carry on with other work, look at the issue at each stopping point, and take the default after 12 hours with no answer. Say so in the PR.
- Where it's merely unclear, take the safer option (easier to undo, or changing the game less) and say so in the PR.
