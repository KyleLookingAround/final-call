# Brief: Tell players when a new version is ready

## Goal and what it may touch

- The owner asked on 27 Sep 2026: when a new version is published while someone is playing, show a toast with a button that loads the latest version. Branch `feature/update-toast` from `main`, one PR.
- The owner's request is the approval for a one-page spec. Write `docs/specs/update-toast.md` from `docs/specs/TEMPLATE.md` with status Approved (by the owner's request, 27 Sep 2026) and the choices below, then build it in the same PR.
- **How it should work** (the safer defaults; change one only with a reason in the PR):
  - **Build id.** `tools/build.mjs` stamps a build id (a short hash of the built page) into the page, and writes it to `dist/version.json` next to `index.html`, so the existing Pages workflow deploys it with no workflow change.
  - **Only on the published site.** It runs only when served from GitHub Pages, detected the same way as the feedback link in Help. It never runs in `R.sim`, in `build/test.html` or from a local file, and never in the headless bot.
  - **Checking.** The game fetches `version.json` with `cache: 'no-store'`. It checks every 10 real minutes and when the tab becomes visible again, but not in the first minute after loading. It is quiet on any network error, sends nothing, and fetches nothing else.
  - **The toast.** When the id differs from the running one, one toast says "A new version of Final Call is ready" with **Update now** and **Later**, in the game's existing toast style and UK English.
    - Update now saves the game, then reloads the page past the browser's cache.
    - Later hides the toast; it comes back no sooner than an hour later in that tab.
    - Never more than one at a time. It doesn't show during the guided start or over the level-up card; it waits until they close.
  - **Saves.** Saving before reloading is enough: the new version loads the save through `resetAll`, as it always does. Never lose progress: if the save fails, don't reload.
  - **What's new.** After the reload, the existing What's new card shows only if the version number went up. Leave that as it is.
- **Files it may touch:**
  - a new `src/game/37-update-check.js` (37 is free; the real-airport parts use 51 to 55);
  - `tools/build.mjs` for the build id and `version.json`, and its `window.__sim` list if a test needs something;
  - a new check group `tools/checks/update.mjs`. It routes `version.json` in Playwright and tests:
    - no toast when the ids match;
    - the toast when they differ;
    - Update saves and then reloads;
    - Later holds it back for an hour;
    - nothing runs off Pages or in `R.sim`.
  - the spec, `docs/SYSTEMS.md` (a short section, and the new check group), the project notes' file table (the `37-update-check` row), this brief as `docs/briefs/update-toast.md`, and a look back in `docs/LESSONS.md`.
- Anything else is outside the brief, including `10-events-toasts.js`: use `toast()` as it is. If it truly can't do this, say why in the PR and make the smallest change.
