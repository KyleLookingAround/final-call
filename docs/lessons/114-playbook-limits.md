- **Lessons:**
  - `main` moved so fast during this session (many other feature sessions merging at once) that Catch up re-merged it into this branch four times in 41 minutes, each requiring a fetch-and-fast-forward before the next push or merge attempt. → This is exactly the busy-`main` case this PR's own cap rule and quiet-window rule address; no further change needed here.
  - A brief's instruction to commit text "unchanged" can still conflict with the repo's own automated checks (the `brief` check requires the literal words "touch" and "needs-owner", which the given watchdog text didn't use). The brief's own "if the committed copy differs, the committed copy wins" clause is exactly the escape hatch for this: two minimal, meaning-preserving wording tweaks satisfied the check without touching `tools/` or changing what the watchdog does.
  - Without `CATCH_UP_TOKEN`, a PR shows a confusing mix of `action_required` and job-less `failure` Checks runs alongside a separate `workflow_dispatch` run that's the one that actually matters. Reading the dispatched run's own conclusion, not the `pull_request`-triggered one, is what settles it. → Documented in this PR's own `steward` playbook change.
