- **Lessons:**
  - `main` moved roughly ten times during this PR's life (other sessions merging concurrently on a busy launch night), and the Catch-up workflow re-merged it into this PR automatically each time, restarting the Checks workflow from scratch on every new head — the same pattern as #54's lesson, but far more extreme here because so many sessions were active at once. The eventual fix was to stop waiting for a stable head altogether: once Checks had passed reliably on several different heads and Balance was fully green, the squash-merge was attempted directly against whatever head GitHub reported at that moment (`expectedHeadSha`), and it succeeded on the first try despite a Checks run for that exact commit still being in progress — branch protection here doesn't require the newest head's own run to finish, only that the PR is mergeable. → On a night this busy, don't wait for a quiet head before merging; merge as soon as there's strong evidence of green (checks passed on recent heads, Balance green) and let the merge call itself be the final gate.
  - Neither the Balance nor the Description workflow fired on this PR's `opened` event, and a later `edited` event (removing the attribution footer) didn't fire Description either — confirmed by listing `workflow_runs` filtered to the branch, which came back empty for both, while other PRs opened around the same time by the same account did get runs. The cause wasn't tracked down (plausibly something about how this session's PR-creation tool call fired the webhook), but the workaround held: adding the `balance` label started Balance via its `labeled` trigger, and Description has no `workflow_dispatch` and no `labeled` trigger, so it could never be forced — closing and reopening the PR would have kicked it but that's explicitly forbidden. The PR body was checked by hand instead (no Claude/Anthropic mentions, no attribution footer) and the gap was written into the PR description. → If this recurs, it's worth a small addition to `description.yml` (a `workflow_dispatch` trigger, harmless since the check only reads the PR's current title/body) so a session in this position has a legitimate way to force it instead of relying on a manual read.
  - Most of the four-times-estimate cost came from three things, in order: (1) the merge-chase above, entirely CI wait time across a dozen-plus status polls; (2) resolving a real merge conflict with the concurrently-merging `famous-faces` PR (#111) in `03-state.js` and `docs/SYSTEMS.md`, including recomputing and updating the `migrate` check's `GOLD` hashes for all 27 save fixtures, then discovering `main` had since grown an `ADDED`-exclusion mechanism for exactly this kind of new-field hash churn and needing to fold that in too; (3) waiting for two independent full `npm run check` runs (each background-polled to completion) as a sanity check beyond the PR's own required checks. None of these were wasted work, but a brief this size (one file, a switch, six hooks) should probably budget for a launch-night's concurrent-session tax specifically, not just "a couple of merge attempts" — the difference between $5 and $21 was almost entirely traffic, not the feature.
