- **Lessons:**
  - The bulk of the overrun was verification, not the fix itself: several full `npm run check` runs (each a few minutes of real time, replayed into context afterwards) plus many rounds of Playwright screenshots at four phone sizes across two save states, largely because early attempts didn't reproduce the exact layout bugs the brief described and needed empirical measurement (bounding rects, computed styles) rather than reading the CSS and reasoning about it. → Worth trying the shots/measurement pass *before* writing the fix, not after each iteration; the geometry ended up needing three separate JS fixes (a hud-avoidance clamp, a `tourRect` return-shape bug, and a side-panel-overlap clamp) that a single upfront measurement pass could plausibly have found together.
  - `main` moved unusually fast even for this repo's known busy-`main` pattern (documented in #114's lesson): seven Catch-up merges in under an hour, several arriving faster than one CI run could complete, so two consecutive check-suite-completed events were already stale by the time they were read. Waiting out one full CI cycle before checking again, or merging on the first "unstable but checks green" read rather than waiting for "stable", would have saved a couple of round trips right at the end.
  - A brief's stated default (here, #105's "option A: no pacing change") can be overtaken by the owner's real decision before the PR closes; #105 was closed by a different, already-merged PR before this one opened its own status comment. Reading the issue's current state (not just the brief) before writing the PR description would have caught this on the first pass instead of needing a follow-up edit.
