# Gate cards and the Pier B mover (#119, #120) · 28 Sep 2026

- **Numbers:** session `session_011JCSBdotGPETceXi5rEmsP`, estimate $8 (revised timing: PR open by 10:00 UTC, merge by 11:00, after a usage-limit pause moved the whole brief a few hours). Waited on #113 (terminal-place groundwork) to merge before touching `12-drawing.js`, as the brief asked; it landed at 05:30 UTC, well inside the wait.
- **What it found:** `placeBadges` (`41-airside.js`) only ever checked a stand's card against planes and rooms, never against another stand's card, so two cards close together (reliably reproduced on Midfield, harder to catch mid-overlap on Classic) always drew on top of each other once both had flights. The mover's car was recomputed from nothing every frame: grouped by rounding to a fixed 90px screen grid (so a rider crossing a grid line could flip which existing car "represented" them), drawn at that raw position with no interpolation, and — with nobody riding — animated off `performance.now()` with no memory of where the last car had been.
- **Went well:** both fixes stayed pure drawing (a `V.t`-driven persistent `MV_CARS` array, and a `placeGateCards` pass over the stands `signs` was already drawing), so `scene: drawing never changes the game` and every existing check passed unmoved; no saved field, no `rnd()` call, nothing reachable from `update()`. Writing `tools/checks/phone-bugs.mjs` against the *real* `placeGateCards`/`badgeRect`/`tagRect` functions (not a re-implementation) caught a real bug before it shipped: `placeGateCards` never reserved space for a card that fell back to a tag, so a later card could still land on top of a tag. The full `npm run check` (293/293, 28 pending) ran once, clean, after both fixes.
- **Lessons:**
  - Matching the mover's car to a rider group by the car's *last drawn position* rather than its *last target* mattered: matching by target let a car's target jump up to the matching distance while the drawn position was still catching up from an earlier jump, compounding past the check's own cap (419px against a 220px cap) until the match was against the current position instead.
  - A check that calls the same helper the game draws with (`S.placeGateCards`, exposed automatically by referencing it in the check file) is worth writing the helper to be callable that way from the start, rather than duplicating the placement logic in the check and hoping it matches.
  - Screenshots for a PR don't need to match the issue's exact layout: Classic (what the owner played) rarely produced a *simultaneous* overlap for a still image, but Midfield reproduces it on almost every frame with two flights running. Said so in the PR rather than spending the time budget hunting for a Classic-only moment.
  - #121 (passengers through a wall) didn't get fixed in this PR: reading `route`/`walk` found every doorway-crossing call site already routes correctly, which pointed the likely cause at `paxEase` cutting a corner across a doorway during a big frame gap rather than at the simulation. Left as a comment on the issue rather than guessing at a fix under time pressure with no check to prove it.
