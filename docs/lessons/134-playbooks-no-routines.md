# #134 Playbooks without Routines, auto-merge, CI time limit · 28 Sep 2026

- **Numbers:** about $2.85 against a $4 estimate, ~30 minutes wall clock, 162k of context. One commit, one push. PR opened as a draft straight off `main` (no merges needed). The Description check failed once (the PR body used literal `.claude/…` paths, which trip the same Claude/Anthropic-mention filter the commit hook enforces) and passed on an edit with no push needed. `npm run check` took far longer locally in this session's container than the usual 1–2 minutes (about 25 minutes wall clock for 346 checks, mostly idle waiting on Playwright rather than CPU-bound) — the same slack the CI timeout bump in this PR is meant to cover.
- **Went well:** a fresh review before opening (the `feature` playbook's step 6) caught two real bugs in the drafted playbook text before they shipped: the coordinator's retiring step didn't say to delete the new heartbeat trigger, and the heartbeat's own `create_trigger` call was drafted with `persistent_session_id` set to its own id, which targets a *different* session per the tool's own docs — self-bind needs the parameter omitted, not filled in with your own id. Both were caught by describing the mechanism in enough detail (not just "book a heartbeat") for a reviewer to check it against the tool's actual contract.
- **Lessons:**
  - A PR description that names editor-settings paths (`.claude/…`) with the literal word inside them fails the Description check the same way a commit message would — the project notes already say to call it "editor settings" in commit messages, but a PR body isn't a commit message, and the reminder didn't carry over. → No change needed here: this lesson is itself the reminder, and the fix (avoid the literal paths in PR prose, not just commit messages) is now demonstrated in this PR's own description.
  - Drafting exact tool-call shape into a playbook (which parameter, which mode) rather than a vague description ("book a heartbeat") is what let a fresh review catch a wrong-mode bug before it shipped and silently failed the first time a coordinator relied on it.
