- **Lessons:**
  - The `graph` check treats any `tools/checks/<name>.mjs`-shaped path in a spec as a claim that file exists, whatever the spec's own status says; the exemption is only for a path containing `/new` or `/part(s)`, not for a plain-English "(new)" next to it. A spec proposing a not-yet-written check, without pre-writing it (no checks-first part here), fails `graph` unless it names the check without a full backticked path (`a new `roadmap-card` check group, its own file in `tools/checks/`` rather than `` `tools/checks/roadmap-card.mjs` ``). → Specs for unbuilt work should describe a planned file's name and folder, not its exact path with extension, unless the checks-first pattern is actually being used.
  - The session's "Generated by" footer landed on both the PR description and a plain issue comment (`add_issue_comment`), not just the PR; reading each one back and stripping it, as the brief asked for the PR, needs to cover every GitHub post this session makes, not only the PR body.
