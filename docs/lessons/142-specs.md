- **Went well:**
  - Three graph queries (`12-drawing.js`, `40-layout-drawing.js`, `perf` for #38; `42-terminal.js`, `50-scene.js`, `perf` for #49) named every file needed; each read four source files whole and grepped for the rest, against eight to ten files for each terminal part.
  - #138 re-measured on `main` before setting budgets: Midfield's simulation had nearly doubled (0.129× to 0.248×) and the throttled phone at sixteen stands fell from 4.7 to 3.0 game minutes a second in one day. The approved shares would have been set against headroom that no longer existed, and the numbers decided where refactor 7 went (first). It also timed each pending group with and without `TP_ALL` to price switching them on (`floors` 43 s) before any part paid it.
  - The owner answered faster through an approve-or-decline page (#138: fifteen items in about two minutes, one decline) and through the coordinator's live conversation (#142) than through the `needs-owner` issue's own thread. → For a spec with many choices, offer a sign-off page alongside the issue. A decline with no note needs one short follow-up question with options, not a guess.
  - #142: the Artifact tool's `read` returned the mock-up's full HTML, so the brief's fallback wasn't needed.
- **Lessons:**
  - `perf` measures the simulation and the real airport only draws, so its headroom was the wrong budget to share (#38). → A `scene` check times drawing a frame against the same calibration, and the spec shares that headroom (`docs/specs/real-airport.md`). `perf` named the simulation's functions but not what it times or its budgets; those came from reading the check.
  - The first drawing timings were ten times too fast: `clampCam` works out the view from the zoom before clamping it, so one call from zoom 0.01 put the camera off the map. Caught because the lighting check read black pixels. → Call it twice; check a timing that looks too good against a screenshot.
  - Budgets set before a bundle is built should add up across bundles, not start fresh: the real airport's shares left about 0.02× of drawing headroom (#49). Numbers from different machines don't compare (`perf` gave Midfield 0.129× here against 0.244× in the spec). → The spec records the machine and asks each part for the median of three runs on its branch and on `main`.
  - `main` moved under the spec: #38's local `origin/main` was still the first commit (fetch before branching from it); #66 (a review) branched minutes before #49's approved spec reached `main`; #138 planned around a 15-minute CI limit that #134 raised to 25 minutes after the draft. → Fetch `main` and read what merged just before writing and again before opening the owner's question (`feature` playbook, step 1).
  - The idea board's page shows only the questions; the owner's answers are in its database (`feedback/round2`), read with `ArtifactData`. → Say so in any brief that points at the idea board.
  - The `graph` check treats any `tools/checks/<name>.mjs`-shaped path in a spec as a claim that the file exists; the exemption is only for a path containing `/new` or `/part(s)`. → A spec for unbuilt work names a planned file by folder and name ("a new `roadmap-card` check group, its own file in `tools/checks/`"), not a backticked path, unless the checks-first pattern is used (`feature` playbook, step 2).
  - The tool added its "Generated by" footer to the PR description (#138) and to a plain issue comment (#142). → Read every GitHub post back, not only the PR body (`steward` playbook).
