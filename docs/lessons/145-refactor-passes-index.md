- **Went well:** the passenger-states guard was recorded from `main` in its own commit before any game edit. Its first run on the index named passenger #0 and their new states, which led straight to the bug: `occ()` skipped anyone who had moved between two market states since the snapshot. Temporary instrumentation then compared the index with the old scans on every read (0 differences in about 5,700 reads, on Classic and on 16-stand Midfield) before it was removed.
- **Lessons:**
  - A per-state index is only as exact as the moment it's read. `occ()` recomputes partway through the landside pass, so a snapshot taken earlier in the step misses anyone who entered the market since. The fix: the two places that send passengers in add them (`stateIn`), and the reader takes the union and checks current states. → `docs/systems/terminal.md`, "Passengers by state", says so for the next reader.
  - A list for every state, looked up by name, cost 50 µs a step with 3,200 passengers, more than the two scans it replaced (38 µs). A CPU profile found this in minutes, where `perf`'s ratios could not: they varied 0.118–0.150× between identical runs of `main`, far more than the ±0.02× the brief allowed. → Measure refactors of hot loops with a profile of the functions they change (`Profiler` over CDP, self time per function), and give `perf`'s medians as well.
  - `npm run check` took about 17 minutes on this session's machine, not 1–2, and a 15-minute timeout cut the first run short. A `pkill -f` on the waiting loop's pattern then killed the shell running the checks. Run the whole check in the background, write it to a file and wait on that file.
