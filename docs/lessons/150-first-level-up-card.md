# #150 Release P1: the first level-up and the guided start · 28 Sep 2026

- **Numbers:** session `session_011ki7ARFAgcCbx2cT5nWbuj`, estimate $6, cost about $6.9 at PR-ready. Started 20:02 UTC, PR opened 20:25. UI-only change: no bot run, `PLAY` untouched since nothing here is reachable from `update()`.
- **Went well:** the audit's row 3 (a newcomer's first level-up was a toast the tour hid) turned out to need one line each at the two ends of the queue: `lvlUp` already built `R.lvlCard`, it just also had to refuse it during the tour; `lvlTick` already opened it, it just had to keep waiting until `G.tour.done`; and `tourNext` (both its natural end and the Skip tour branch) just had to call `lvlTick` once it set `done`. No new state, no new saved field. Screenshots at 390×844, 320×568 and 568×320 before the PR opened caught nothing the checks didn't already prove, but confirmed the card's timing felt right, not just correct.
- **Lessons:**
  - `lvlUp`'s old guard, `R.sim||SET().lvlCard===false||(G.tour&&!G.tour.done)`, mixed two different kinds of "off": some belong on the queue (sim, the setting) and some only on the *open* (the tour). Reading it as one list of reasons not to show the card missed that the tour case should still queue. → When a guard combines several conditions, ask what each one is actually gating before changing any of them.
  - Two rendered rows shared one `data-lvgo="plan"` value (the Masterplan points tile and the plans list, and — once level 4 unlocks Consultants — the "Opens up" section too), so a check that counted `[data-lvgo="plan"]` across the whole card silently over-counted by however many of those happened to be on screen. → A shared click target across sections is fine for players; a check that counts by it needs to scope to one section's markup, not the page.
  - The fresh review (a general-purpose agent, since no dedicated code-review agent type is registered in this environment — only the `/code-review` skill, which runs in-session rather than fresh) caught a stale file-header comment the docs update missed, and a real regression: dropping `lvlTick()` from the Skip tour branch specifically (leaving `tourNext`'s own call alone) would have passed every check that existed before its review, because the levelup check only ended the tour via `tourNext`, never via a simulated Skip tour click. → When a fix has two call sites for the same effect, a check exercising only one of them is half a check; confirmed by reverting the fix locally and watching the new test fail, then restoring it.
