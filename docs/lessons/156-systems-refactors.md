# Systems refactors: #81 routes, #85 effects ledger, #86 save fields, #95 clocks and day stats, #98 weather, #145 and #156 passes over passengers · 27–28 Sep 2026

Seven refactors meant to leave the game as it is. They shared one method, and each met its own trap.

- **Numbers:** estimates $6 (#81, $1.71 and 128k), $10 (#85, $3.69), $8 (#86, about $5), $10 (#95), $8 (#98), $20 for #145 and #156 together ($5.53 spent when #156 opened, 24% of context). Each ran seeds 1–3 of the bot locally against a build of `main` and got identical `PLAY` and `STATE` (#95 also `LVLAT`, on seed 1).
- **The method that worked:**
  - Record a guard from `main` in its own commit before any game edit, so the refactor has to meet it (#86's `migrate` hashes, #95's clock order and #98's weather flags, #145's passenger states). #145's guard named passenger #0 on its first run, which led straight to the bug.
  - `PLAY` against `main` needs a local run: the Balance workflow prints the branch's `PLAY` but never compares it with `main`. Use a `git worktree` of `main` in the scratchpad with `node_modules` symlinked, alternate `main` and branch runs (twelve runs on four cores took about ten minutes), and compare with the base commit, not a `main` that has moved on. → In the `balance` playbook; a workflow that prints `main`'s `PLAY` too is proposed in a `needs-owner` issue.
  - A fingerprint of `G` from a page must stop the frame loop (`open(…,{still:true})` stubs `requestAnimationFrame`) or it isn't repeatable (#85).
- **Traps:**
  - #81: the new `graph` warning had to be tuned before it was useful (34 warnings on `main` when it flagged every outside function; three or more from one outside file flags only Routes and two others). Moving `const` arrow functions later in the join is a load-order risk only for calls at load time.
  - #85: a file numbered before `42-terminal.js` can't add to `SIMX` at load time; the check read the cause tables through `__sim.R.effects` (the `__sim` list has since become automatic, #94). Switching layout while passengers are in the terminal crashes the next step (`faceW` on a stand that's gone), so a check that wants several layouts uses a fresh page each, switched before play.
  - #86: two `FIELDS` defaults weren't pure (`hotelBook` reads `G.clock`); a default that reads `G` is fine in `resetAll`, not in `DEFAULT()` called elsewhere (`migrate()` drops it). `tools/graph.mjs` parsed `DEFAULT()`'s literal text, so reshaping it broke `graph` although the file wasn't in the brief: a tool that reads source by regex is part of the code it reads, so grep `tools/` for a function's name before reshaping it.
  - #95: the per-minute order wasn't "minute, hour, night" (`crewTick` sits between the two hourly hooks, `nightChecks` runs before the hourly advertising cost); running `HOUR` as an entry of `MINUTE` and `NIGHT` as an entry of `HOUR` kept it exact, and recording the order first is what showed it. `G.dstat`'s key order is part of `STATE`. A shared helper named `tick` clashed with `06-sound.js`'s; the duplicate-name check caught it. → Search `src/game/` for a short name before giving it to a new top-level function.
  - #98: the spec's `wx` was already taken (a stand-to-world transform in a groundwork file), and the brief's file list named `04-effects.js` while `R.fx` is read in `04-geometry.js`. → Search `src/game/` for a new top-level identifier before writing code, and check a brief's file list against `grep -l` of what the change touches. `R.fx` also holds non-weather flags; `docs/systems/weather.md` says which is which.
  - #145: a per-state index is only as exact as the moment it's read: `occ()` recomputes partway through the landside pass, so an earlier snapshot misses anyone who entered the market since. The two places that send passengers in add them (`stateIn`), and readers take the union and check current states (`docs/systems/terminal.md`, "Passengers by state"). A list per state, looked up by name, cost 50 µs a step at 3,200 passengers, more than the two scans it replaced (38 µs); a CPU profile found it in minutes where `perf`'s ratios varied 0.118–0.150× between identical runs of `main`, against the ±0.02× allowed. → Measure hot-loop refactors with a profile (`Profiler` over CDP, self time per function) and give `perf`'s medians too.
  - #156: "merge the three passes in the order they run today" can't hold `PLAY`, since the vehicles, weather and events between the passes draw on `rnd()`; only passes next to each other in `update()` merge exactly (`docs/systems/terminal.md`, "Passes over passengers"). The second PR was prototyped on a local branch while #145's CI ran, then cherry-picked onto the new `main`.
- **Machine hygiene** (seen in #81, #85, #89, #92, #94, #116, #117, #145, #149; in the `feature` playbook, step 4): the `news` group's click timed out in full runs whenever something else loaded the machine (bots, a second build, a reviewer running checks, several log-polling loops) or zombie Chromiums from repeated local runs were left; it passed alone. `pkill -f <pattern>` in a command whose own line contains the pattern kills that shell (exit 144: #81, #92, #145); kill by PID.
