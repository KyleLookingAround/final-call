# Release batch F1: tips that point the right way (#148, #166) · 29 Sep 2026

- **Numbers:** estimate $15; the session's cost wasn't reported yet when the PR opened. Started 03:18, PR opened 04:01: six rows plus the 4× text, one new check group (`tips`, 11 checks), bot seeds 1–3 before and after, one full local check run and a rerun of the five groups it failed.
- **What it found:** on `main`, seed 1 no longer reaches International in 1,150 hours (City Airport at 149.7, then stuck at about 6,000 a day against 8,000). It did in the release audit's runs, so something merged since (two floors in Classic, #162, is the only game change in between) moved it. It isn't this batch's, and it isn't a tip: the bot holds 2 planes a gate and partners fill the rest. Reported in the PR for B1 (#147), which owns pacing.
- **Went well:** starting the baseline runs from a copy of the `main` build (`../f1-base`) before touching code, so the before and after ran side by side without a worktree; the audit's rows named the functions, so the graph and four files were all the reading needed.
- **Row 5's proof is the bot, not a scripted guided run:** the audit's guided-only player (`build/audit/itch/`) wasn't committed, so the `tips` group plays its own follower (tips, the goal bar, plans and the gates a level asks for). It reaches Regional in 200 hours, not City Airport, so it proves the fare cap and the rating tip's share but can't show the City Airport wall lifting. → A scripted player that follows the game's own guidance is worth keeping as a tool (`tools/`), so the next guidance change can measure it.
- **The full run found what the group runs didn't:** four groups outside the ones I'd been running (`market`, `daystats`, `rating-day`, `graph`) failed on purpose-made changes. One was an old check asserting the audit's bug (a café upgrade at MAX), and one was a marginal pass mark (fog's pull, 1.04 against 1) that gate servicing moved to 0.83. Proving the cause took one throwaway edit (servicing switched off, the same numbers as `main`), rather than guessing. → Run the full `npm run check` once as soon as the game code is in, not only at the end: the groups a change breaks aren't always the ones it names.
- **The fresh review earned its keep:** it caught a tip that would loop for ever ("replace with bigger planes" never went away, since buying one doesn't sell the old). A rule for any tip or recommendation that buys something: say what makes it stop.
