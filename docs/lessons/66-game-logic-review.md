# Reading the game's logic: #57 game logic ideas, #66 systems review · 27 Sep 2026

- **Numbers:** #57 estimate $8, $3.01 and 186k at the first merge attempt; #66 estimate $15, cost not reported by the time the PR opened. Both docs only, no Balance run. The three bot runs on `main` ran in the background from the first minute (about 12 minutes side by side) while the code was read; #66 also had four helper agents map the region, the terminal's hooks, the UI and the tools (about 4 minutes each) and read their reports in place of the files.
- **Lessons:**
  - The bot's six-hourly snapshots already hold most of what a look at the game logic needs: cash, rating, the day's passengers, gates, supply against the market, idle stands, plans left, and the `why` field (rating causes, which requirement holds each level, cash floors). A 20–30-line script that divides each level requirement by its target at each snapshot shows which one holds each level back, without adding anything to the bot. Seen again in #101 (`rdS`, the day's net score per departure, made the tuning a calculation) and #117 (a 20-line script over `tools/bot.js` with `every:1` traced the first two days by the hour). → The `balance` playbook now says to trace the bot before touching baselines. A `--why` summary in the bot would save the next script, and is a tools change for a session that may touch `tools/`.
  - A play of the bot's saves showed what the logs can't: five departures on the board all to New York, partners flying every short-haul route, four bus lines at one service an hour carrying nobody. → A review of the game logic plays a save at three levels and reads the board, the Routes tab's report and the Region tab; a 60-line Playwright script does it in a minute.
  - `Object.assign(window.__sim,SIMX)` copies a getter's value, which was the whole of the `__sim.AF_Y` bug the planes part met (`ROOF` had the same). → Refactor step 1, with a build rule; any live value for tests belongs in the `__sim` list the build makes.
  - Reading `graph.mjs` for `update`, `checkLevel` and `dayTick` pointed at the right files first time; the long one-line functions meant reading with `cut -c` to keep the context small.
