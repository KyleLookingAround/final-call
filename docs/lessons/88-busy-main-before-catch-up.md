# A busy `main` before one file per entry: #54, #83, #88, and the merges other PRs needed · 27 Sep 2026

On 27 Sep about a dozen sessions all wrote the top of `docs/LESSONS.md` and the one-line check list in `docs/SYSTEMS.md`, so nearly every push conflicted, and a conflicted PR got no CI at all. #94 fixed it (one file per entry, the Catch up workflow, `docs/decisions/ADR-2026-09-27-fewer-clashes.md`). This is the record of what it cost.

- **Numbers (merges from `main` by hand):** #54 Ko-fi link: six merge attempts, estimate $6, past $12 by the sixth, entirely merge-chasing. #83 rebuild-twice fix: three pushes, each merging `main` (about a dozen PRs that evening), estimate $6, about $3.50 at merge; CI never started on the first two. #88 masterplan on a small phone: six or more, estimate $5, well over. Others in the same window: #47 three, #64 two rounds plus a `tools/build.mjs` conflict (estimate $6, $13.55), #79 seven, #81 four, #85 five, #86 four, #92 several (estimate $6, about $18), #94 five. The worst before was eight.
- **Lessons:**
  - GitHub runs no `pull_request` workflow while a PR conflicts with its base, and `mergeable_state` lags; the fully reliable signal was `merge_pull_request` refusing outright with a 405. Dispatching `checks.yml` and `balance.yml` by hand on the branch got a real signal. → `steward` playbook: check `mergeable_state` before waiting on CI. Don't dispatch `parts.yml` on a PR that isn't a split feature's part: it runs the same job for every open `part:` PR and posted an unrelated failure on #54.
  - Every conflict was in shared lists (`docs/LESSONS.md`, the checks line in `docs/SYSTEMS.md`, `docs/ROADMAP.md`, `tools/build.mjs`'s old `SIMX` list), never a PR's own files. A brief that deliberately defers docs to a later merge trades a smaller diff for at least one extra guaranteed merge-chase (#64), and a tightly scoped file list is what kept #87 out of the chase. → Fixed by #94; a PR opened before it needed one hand merge to take it in (#88 was the first lesson filed under the new scheme).
  - Stopping at the brief's two merges would have left a PR unmergeable: GitHub refuses the squash merge on a conflict, and a green check doesn't stay true for the seconds it takes to call the merge (#54, #85).
  - #83: a flight on a moved stand is held by more than `R.st`: `F.i`, `F.arr.stand`, each passenger's `p.stand`, the runway queue and the fleet's `gate`; grepping `\.stand\b` and `F\.i\b` found them all in a minute (`docs/SYSTEMS.md` says what a switch does with them). The new check's first run failed only because a flight was still waiting for a late passenger; print the flight's state before suspecting the fix.
  - #88: scrolling a variable-height target into view on a small screen should target the smallest anchor that proves the section is reachable (`[data-sec="ready"]`, not the whole ready card), and only a check that measures pixels catches a later regression; merging `main` in (a touch-target batch that grew `.chip` padding) broke it again.
  - #54: screenshots need the guided-start coach mark and spotlight hidden explicitly (`#coach`, `#spot`); GitHub Actions dropped the `pull_request` trigger on its first two pushes (a manual `workflow_dispatch` gave a real signal, and the trigger fired on every later push).
