- **Lessons:**
  - The fresh review before opening caught a real bug the new check didn't: the region-news fold matched incidents by message shape only, not by which line had failed, so a wire fault on one line and a signal failure on another folded into one line that still named only the first line's code — implying one line had failed repeatedly when several different ones had. The check written alongside the bug asserted exactly that wrong output, so it would have locked the bug in rather than caught it. → No playbook change: a reminder that a check written in the same pass as the code shares its author's blind spot, which is exactly what the fresh-review step is for.
  - Chasing what looked like a flake this branch had introduced (the `news` check's Playwright timeout clicking `[data-news]`) cost most of the overage: a controlled clean-vs-modified comparison across several full-suite runs, before finding the real cause was accumulated zombie Chromium processes from repeated local re-runs, not the code. Cleaning them up with `pkill -f chromium` killed the shell running that very `pkill`, since its own command line contains the pattern it was matching — lost another cycle before spotting that. Both turned out already on record from "Systems refactor 2" the same day (kill by PID, or a pattern the invoking command doesn't contain; the `news` timeout is pre-existing, cross-session, and the terminal-place checks PR's to fix). → No new fix needed, just a second data point for both; a reason to check the newest lessons before spending time diagnosing something that looks environmental.
  - The brief's file list left out `docs/SYSTEMS.md` on purpose (heavy write traffic today across a dozen sessions); a fresh reviewer given the diff and the brief, but not told why, still flagged it against the general project-notes rule. Said so in the PR rather than changing course, but a brief that deliberately omits a normally-required file might as well say why in the same line, so a reviewer isn't told twice.
  - `tools/build.mjs`'s SIM-exposure list moved to auto-discovery mid-PR (#94): the manual `toast,dropToast,tickToasts,renderTip,renderNews` addition this PR made became dead weight the moment the new mechanism landed, since it finds every `S.<name>`/`__sim.<name>` a check file uses on its own. Taking `main`'s version of the file wholesale at that merge, rather than trying to reconcile the two list-shapes, was the fast and correct move.
