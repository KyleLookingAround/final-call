- **Lessons:**
  - The first way of claiming a release version, a `git push` of the new branch, can't stop a second claim: a push to a branch that already sits at the same commit succeeds quietly, even with `--force-with-lease=<ref>:`. The fresh review suspected it and a scratch test proved it. → The `release` playbook claims the version by creating the branch through GitHub's API, which refuses a branch that already exists.
  - A PR that restructures files other sessions are editing at that moment will need a real merge each time one of them lands (five here). Merging `main` in right before merging is the brief's own rule for this PR; after it, a new check group or a `__sim` entry no longer touches a shared file.
