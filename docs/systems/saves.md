# Saves

**Saves** stay on the device (`localStorage`). The game is published only on GitHub Pages; Office › Settings › Save copies and pastes a save code to move an airport between devices. Saves across devices through the old hosting page were removed; `22-save.js` clears their old keys once on load. A quiet Ko-fi link sits at the foot of Settings, under Your save (`docs/specs/kofi-link.md`).
- **Load** (Office › Settings › Save, `loadSave` in `15-panel.js`). The pasted code must decode to an object with a numeric `cash` and a `stands` array. The first tap arms the button ("Tap to replace this airport") and it goes back to "Load" after 3 seconds; a second tap inside 3 seconds replaces the airport. The `saves` check plays it through.
- **Saved fields and loading** (`FIELDS` in `03-state.js`, `MIGRATIONS` in `22-save.js`; check `migrate`). `FIELDS` maps every saved field of `G` to `() => its default`; `DEFAULT()` is a new game built from it, and the terminal's parts add their fields to it from their own files (as `TERM_FIELDS`). `resetAll(state)` loads any save in three steps: the save's fields over the table (a field missing or null takes its default, with `G` already in place, since a default may read the airport), then `MIGRATIONS`, an ordered list of `{when(state), up(state), note}` run in order, where `state` is the save as stored (null for a new game), then the runtime reset (`R`) and, outside the headless sim, the screen. A new saved field needs only its line in `FIELDS` (or `TERM_FIELDS` in a part's file); add a step at the end of `MIGRATIONS` only when older saves need more than the default. Never rename or remove a field. The `migrate` check loads every save in `tools/saves/` with the same seed and compares a hash of the result with one recorded for each file, so any change to what a save loads to fails it; a new fixture fails until its hash (printed by the check) is added to `GOLD` in `tools/checks/migrate.mjs`. It also checks every field of `DEFAULT()` is in `FIELDS`.
- **Never losing a save** (`save()`, `stopSaving`, `newerSave` in `22-save.js`; `frame`, `start` in `23-boot.js`; check `saves`). Saving stops, and a warning says why (shown whatever Settings › Alerts says), in four cases, named by `R.saveBlock` or `R.frameErr`:
  - **Another tab saved since** (`'tab'`). `R.lastWrite` is the stored text this page last read or wrote; if the stored text differs when it next saves, someone else wrote it, so this page stops. Its warning offers Reload.
  - **A newer build wrote it** (`'newer'`). Every save carries `G.ver`, the What's new version of the page that wrote it (`FIELDS.ver`, added in `22-save.js`). A stamped save with a later version, or with upgrades or cities this page doesn't know (which loading would drop), is loaded but never saved over.
  - **Loading it failed** (`'broken'`). `resetAll(state, raw)` catches a throw while loading a save, copies `raw` (the stored text) to `final-call-save-v2-broken`, and starts a fresh airport (no guided start) that won't save, so the stored save stays byte for byte. Start afresh saves from there; Copy save copies the broken save's code. In the headless sim, or for a new game, the throw still surfaces.
  - **An error in a frame** (`R.frameErr`). `frame()` runs its body in `try`/`finally`, so the loop always carries on; the first error pauses the game, stops saving and says so. Carry on resumes both; Copy save copies the last good save.
  - A save that fails to write (storage full) says so once, until one succeeds.
- **Welcome back** (`welcomeBack` in `23-boot.js`). Loading a save more than 90 seconds old pays, for each second away up to three hours, 0.35 of a typical game minute's profit (the median of `G.hours`' finished hours, revenue less costs, over 60): at normal speed a second is a game minute, so it is about a third of what the airport would have made. It goes straight to cash, `G.earned` and `revBy.bonus`, never through `earn()`, so it stays out of the hour's and day's takings and the minute's rate (`R.minEarn` → `G.rate`), and reloading can't snowball it.
